## Detailed Test Cases

### TC-04-001: Port Profile Creation and Retrieval with Channel Depth Datum
- Description: Verify that a Port Administrator can configure and fetch the port profile, including official name, UN/LOCODE, time zone, and controlling navigation channel depth datum.
- Level: API
- Severity: Blocker
- Governing Contracts: CT-01, CT-02, CT-17 (port_profiles, navigation_channels)
- Preconditions: Database seeded with Port Admin credentials (`admin.damietta`), active session established.
- Endpoint / Page ID: `POST /api/v1/port-profile`, `GET /api/v1/port-profile`
- Steps:
  1. Authenticate as Port Admin.
  2. Send `GET /api/v1/port-profile` to verify initial setup state.
  3. Send `PUT /api/v1/port-profile` with payload:
     ```json
     {
       "name": "Port of Damietta",
       "unlocode": "EGDAM",
       "timezone": "Africa/Cairo",
       "coordinates": { "latitude": 31.4285, "longitude": 31.8152 },
       "controlling_depth_datum": "LAT",
       "version": "2026-11-01T00:00:00.000000Z"
     }
     ```
- Expected Result: HTTP 200 OK. Response returns updated port profile, microsecond-precision `updated_at` version token, and sets the active controlling depth datum for channel calculations.
- Evidence: JSON response body, database row in `port_profiles`.

### TC-04-002: Navigation Channel Controlling Depth and Speed Limit Validation
- Description: Validate that navigation channel updates reject negative, zero, or out-of-range depths and speed limits.
- Level: API
- Severity: Major
- Governing Contracts: CT-01, CT-17 (`chk_channel_dimensions`)
- Preconditions: Port profile exists; channel `navigation_channels.id = 1` seeded.
- Endpoint / Page ID: `PUT /api/v1/navigation-channels/1`
- Steps:
  1. Send `PUT /api/v1/navigation-channels/1` with `depth = -14.5` and `speed_limit_knots = 0`.

- Expected Result: HTTP 422 VALIDATION_FAILED. Problem details response body contains RFC 9457 shape with error keys `errors.depth: ["validation.min"]` and `errors.speed_limit_knots: ["validation.min"]`.
