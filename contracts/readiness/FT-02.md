## Endpoints (merged to develop)

| Method and path | Roles | Purpose | Task |
| --- | --- | --- | --- |
| `POST /api/v1/auth/login` | Public | Web sign-in; starts a new session | P1-C1 |
| `GET /api/v1/auth/me` | Any signed-in user | The signed-in user's profile | P1-C1 |
| `POST /api/v1/auth/change-password` | Any signed-in user | Changes the password and clears `must_change_password` | P1-C2 |
| `POST /api/v1/auth/logout` | Any signed-in user | Web: ends the session. Mobile: revokes the Bearer token of the request; the user's other devices keep theirs | P1-C2 · P1-C4 |
| `POST /api/v1/auth/mobile/login` | Public | Mobile sign-in: returns an opaque device token, valid 30 days from the last use | P1-C3 |
| `GET /api/v1/system/info` | Public | Port id, code and name, licence mode and the minimum app version | P1-C5 |

**Web:** first call `GET /sanctum/csrf-cookie` (framework route, 204) and send the `XSRF-TOKEN` cookie's value as `X-XSRF-TOKEN` on every write. The header is for the web session only; a request with a Bearer token is never refused for its absence.

**Mobile (Bearer):** every signed-in request sends `Authorization: Bearer`, `X-App-Version` (`x.y.z`) and `X-Device-Id`. A missing or malformed one is 422; a version below `min_app_version` is 426 with `min_app_version` in the body; another device's token, or a revoked one, is 401. Every write with a Bearer token (logout and change-password here) sends an `Idempotency-Key` (UUID v4): the same key and body within 24 hours replays the first answer, the same key with another body is 422 `IDEMPOTENCY_KEY_REUSED`, and a missing or malformed key is 422. `POST /auth/mobile/login` is exempt: a token is never replayed. A replayed answer carries the header `Idempotent-Replayed: true`; a retry that arrives while the first request is still running gets 503 `SERVICE_UNAVAILABLE` with `Retry-After`. `X-Device-Id` is a string of at most 100 characters; a missing or malformed header is 422 and the `errors` key is the header name (for example `X-Device-Id`).

## Examples

The error bodies were captured from `develop` through the Laravel test client on the MySQL schema database, not from a deployed server. The exception is the "not signed in" text of the 401, which comes from `lang/en/errors.php`. The success examples follow CT-03; the captured responses have the same fields. `id` and names are examples.

### Statuses per endpoint

| Endpoint | Success | Errors |
| --- | --- | --- |
| `POST /auth/login` | 200 | 400 · 401 · 403 · 419 · 422 · 429 |
| `GET /auth/me` | 200 | 401 · 403 · 422 (Bearer headers) · 426 |
| `POST /auth/change-password` | 200 | 401 · 403 · 419 · 422 · 426 · 429 · 503 (Bearer: a retry while the first is running) |
| `POST /auth/logout` | 204, no body | 401 · 403 · 419 · 422 (Bearer: header or key) · 426 · 503 (Bearer: a retry while the first is running) |
| `POST /auth/mobile/login` | 200 | 401 · 403 `ACCOUNT_DISABLED` or `DEVICE_REVOKED` · 422 · 426 · 429 |
| `GET /system/info` | 200 | 503 |

`403 ACCOUNT_DISABLED` is the 403 of the web endpoints; mobile sign-in can also answer `403 DEVICE_REVOKED` (a device the Port Admin cancelled). `PASSWORD_CHANGE_REQUIRED` (403) applies to the other signed-in routes, such as `/users`, until the password is changed; `me`, `change-password` and `logout` stay open. A Bearer request to any signed-in route can also be 426 or 422 (app headers).

### POST /api/v1/auth/login → 200

```json
// request
{ "username": "staff.ahmed", "password": "••••••••" }
```

```json
// response
{
  "id": 41,
  "name": "Port Staff",
  "role": "PORT_STAFF",
  "terminal_ids": [],
  "must_change_password": false
}
```

### GET /api/v1/auth/me → 200

The same profile as the sign-in answer. `role` is null when the user has no active role (a Port Admin can end a role, FT-03): such a user still signs in and gets `role: null` and empty `terminal_ids`.

### POST /api/v1/auth/change-password → 200

```json
// request
{
  "current_password": "••••••••",
  "new_password": "••••••••",
  "new_password_confirmation": "••••••••"
}
```

The response is the profile, with `must_change_password` false.

The new password has at least 8 characters with letters and numbers, equals its confirmation, and differs from the current one; the current one must be right. The 422 `errors` keys are `current_password`, `new_password`, with the messages `validation.current_password`, `validation.confirmed`, `validation.different` and `validation.password`. It is throttled at 5 requests per minute per user, every request counted, then 429. A password change closes the user's other sessions: on web the other sessions end, on mobile the user's other tokens are revoked and the token of this request stays.

### POST /api/v1/auth/mobile/login → 200

```json
// headers: X-App-Version: 1.2.0 · X-Device-Id: 7d9e0f2a-3c41-4b8a-9f10-5e2a6b7c8d90
// request
{ "username": "pilot.k", "password": "••••••••", "platform": "ANDROID" }
```

```json
// response
{
  "token": "12|Hk3s9QxV0pLw2mN8rT5yZb7cD1fG4jK6aE0uI3oP9s2a5b8c",
  "expires_at": "2026-12-22T10:00:00.000000Z",
  "user": {
    "id": 41,
    "name": "Capt. Karim",
    "role": "MARINE_PILOT",
    "terminal_ids": [],
    "must_change_password": false
  }
}
```

`expires_at` is the value at sign-in only: each use moves it 30 days later, so rely on 401. A new sign-in from the same device revokes that device's older token. `platform` is `ANDROID` or `IOS`.

### GET /api/v1/system/info → 200

```json
{
  "port_id": "0d9f6a52-7c1b-4b7e-9a3e-5a2f1c8d7e10",
  "port_code": "EGDAM",
  "port_name": "Damietta Port",
  "license_mode": "FULL",
  "token_warning_days_left": null,
  "min_app_version": "1.0.0"
}
```

No sign-in, and never 426. `license_mode` is always `FULL` and `token_warning_days_left` always null until the licence work (DEC-54). It answers 503 while the port is not provisioned yet.

## Known gaps

- **Rate limit:** on sign-in only failed attempts count (5 per minute for one username from one address, 20 per minute for one address, web and mobile together); a successful sign-in never counts. Change-password is different: 5 requests per minute per user, every request counted.
- **Revoked device:** the Port Admin can cancel and restore a device (FT-03). Until restored, mobile sign-in from it is `403 DEVICE_REVOKED`.
- **Dev server:** none until P6-R6 or an earlier host (DEC-47).
- **Web-app origin:** it must be listed in `SANCTUM_STATEFUL_DOMAINS`. Otherwise login answers 400.
- **Frontend review:** the Frontend Team has not reviewed these endpoints (P1-C1, P1-C2).
